# DevCenter stack evaluation

Current scope: collapsible projects containing sessions, built-in plugin tabs, and SQLite metadata. At the user's request, previously running commands launch anew on application startup. Definitions and current openings are distinct; closing a tab retains its metadata internally. New tab creates a fresh opening from a user YAML type; the saved-definition reopening selector is no longer exposed. Each terminal has an independent PTY and emulator. This does not mark all interactive validation checks complete or certify every supported Linux environment.

The opt-in `dcodex` action resumes a saved Codex conversation on a new process launch. Per-invocation `SessionStart` and `UserPromptSubmit` command hooks record the native conversation ID to an atomic, generation-fenced file keyed by stable session/tab IDs in application data. The GUI dispatches the wrapper/hook through its running `/proc/<pid>/exe` image; a standalone helper is also available. The wrapper remains as the terminal leader, waits for Codex, and resumes the latest hook-recorded ID after exit with a two-second delay and a five-rapid-exit cutoff. Terminal interrupts reach Codex while the supervisor ignores SIGINT/SIGQUIT; the child restores default dispositions before exec. Codex runs with `--no-daemon` inside the existing terminal containment. Closing the tab or Quit kills the supervisor and descendants together. This adds no persistent host, terminal engine, transcript parser, or global Codex configuration edits. As in Agent Orchestrator, the wrapper passes the invocation-wide hook-trust bypass flag so session-flag hooks execute; this also permits other enabled hooks without review. Missing history never triggers an implicit fresh conversation. See README for configuration and limitations.

## Candidate and licensing

The inspected and installed candidate is [`coder/ghostty-web`](https://github.com/coder/ghostty-web), npm version **0.4.0**, pinned in package.json and package-lock.json. Its package metadata and [upstream license](https://github.com/coder/ghostty-web/blob/main/LICENSE) declare MIT. Published runtime dependencies are empty. Upstream's development tools include xterm packages for comparisons; this application neither installs nor uses those packages.

This is a third-party integration around a patched Ghostty WASM build, not a supported native Ghostty surface or a promise of official browser support. Before distribution, include the applicable Ghostty and ghostty-web license notices and record the source revision/build provenance for the shipped WASM.

The Ghostty VT engine handles byte parsing and screen state. **WASM alone is not a browser terminal.** ghostty-web provides Canvas rendering, font measurement, input encoding, selection, clipboard integration, mouse handling, and scrolling in TypeScript. Every one of these browser-facing behaviors must be tested under WebKitGTK rather than inferred from native Ghostty or Chromium.

## API actually used

The installed declarations and distributed JavaScript were inspected, alongside [upstream sources](https://github.com/coder/ghostty-web/tree/main/lib). The prototype uses `Ghostty.load(assetUrl)` and a `Terminal({ ghostty })` rather than relying on `init()` to guess an asset path. Vite imports the package's exported WASM with `?url`, placing a fingerprinted local asset into the build. No CDN is used at runtime.

Other used APIs: `open`, `write(Uint8Array)`, `onData`, `onResize`, `FitAddon`, `paste`, `getSelection`, `buffer.active.getLine().translateToString()`, `dispose`, and `attachCustomKeyEventHandler`. In this version the custom handler returns true when it handles an event. Its semantics differ from some other terminal APIs despite the compatibility-oriented names.

In 0.4.0, `write` parses into WASM synchronously; its optional completion callback is scheduled through requestAnimationFrame. The output ACK is sent after the synchronous parse, without waiting for a paint, because hidden-window animation frames may pause. Reevaluate this assumption when upgrading the library.

## Ownership and limits

- `TerminalSession` owns the PTY and child independently of React. Commands address a session ID. This provides a boundary that can later move behind a daemon; no daemon exists here.
- Rust reads raw bytes in chunks up to 16 KiB. Exactly one data envelope can remain unacknowledged in the Tauri channel. Reading stops until the frontend ACKs, so pressure propagates back to the PTY producer. A raw byte/resize replay journal is bounded by a 4 MiB per-session accounting budget; replay holds at most one additional bounded copy plus a live chunk. On overflow the journal is discarded and reconnection explicitly warns that the previous screen cannot be restored. On natural exit, the reaper allows up to an additional 1 MiB of bounded PTY tail draining without frontend ACKs so native handles/workers can be released even if the frontend is detached; the IPC envelope window remains one. Excess tail is explicitly discarded with an error. Bounded plain-text frontend snapshots are persisted separately; the raw replay journal remains memory-only.
- JavaScript converts byte arrays directly to Uint8Array. It does not decode each chunk independently. Ghostty retains partial UTF-8 and VT parser state.
- Scrollback is configured to 2,000 lines. Input has a 64 KiB frontend budget, 8 KiB native writes, and a bounded one-request native input queue. A dedicated writer avoids holding the session lock while waiting for PTY input space.
- React keeps one persistent controller per tab, keyed by its stable ID inside its session. Container resizing uses ResizeObserver and ignores zero-sized containers. Closing explicitly disposes emulator resources and subscriptions. Tab/session selection and reordering change visibility/order rather than mounting new terminals.
- Sessions retain their own selected tab. Session IDs identify a launch; stable tab IDs identify configuration across explicit stop/restart. Sessions are indexed by tab ID, not session ID. Session closure checks confirmation before terminating any of its tab sessions. The UI uses the same registry methods shared with CLI control.
- Tab configuration contains an optional directory override, optional executable, argument array, explicit environment overrides, and optional explicit shell-command mode. Rust resolves the current session directory at launch when no override exists. Shell-command mode invokes the user's shell with `-lc`; direct mode passes literal arguments without shell evaluation. The inherited environment is not stored in metadata. New PTYs prepend the application executable directory to their default PATH so the sibling devcenter CLI is available without personal PATH or shell configuration changes. Explicit project/action PATH overrides win; this runtime default is not saved in tab metadata.
- All controllers share the loaded Ghostty WASM instance but use separate terminal handles. Hidden sessions still parse and ACK raw bytes; their public `CanvasRenderer.render` method is gated off. Document-hidden windows also suppress painting; restoring visibility fits the container and forces a redraw. Upstream's lightweight per-terminal animation/cursor polling remains; private animation-loop fields are not patched. Recheck this adapter when upgrading ghostty-web.
- The authoritative terminal screen is in the frontend's existing Ghostty instance. The snapshot adapter reads that buffer, limited to the visible screen and 65,536 JavaScript code units. There is no second emulator and no regex ANSI stripping. The future CLI must report snapshot-unavailable when this frontend is disconnected. A hidden but connected frontend supplies snapshots from the same emulator; native lifecycle checks verify continued output while hidden.

## Open blockers and limits

1. **Mouse browser adapter:** `src/terminal-mouse.ts` supplies the browser forwarding missing from ghostty-web 0.4.0. It reads Ghostty mouse modes and forwards SGR/legacy press, release, drag and wheel events as raw bytes through the bounded input queue. Shift-drag retains local selection; Ctrl-click is reserved for native link activation. The isolated native Wayland curses check now receives mouse reports. This resolves that observed blocker on the tested host; it does not certify all mouse protocols or other desktops.

2. Remaining interactive Codex and browser-facing checks are tracked in the native validation checklist. User feedback authorized the sidebar work; builds and engine checks alone still do not certify those behaviors.
3. Terminal launch requires writable systemd user cgroup v2 delegation, cgroup.kill, and pidfds. The bootstrap re-execs the live application through `/proc/<app-pid>/exe`, preserving the same image/protocol even if a rebuild or update deletes/replaces its original pathname. `current_exe()` can return a nonexistent path ending in `(deleted)` and must not be used as the production launch path. The bootstrap joins a new per-terminal cgroup before exec; failure rejects launch, without a process-group or /proc fallback. Confirmed close/Quit atomically SIGKILL the cgroup and wait for it to empty. This includes inherited descendants that setsid or double-fork. A short-lived watchdog outside the leaf monitors application and command-leader pidfds, kills the leaf on either death, removes it, and exits. Leader exit intentionally ends its remaining background jobs. No graceful interval or persistent daemon is implemented. This is not a security sandbox: deliberate same-user cgroup migration and work delegated to external services are outside ownership. The implementation is Linux/systemd-specific; non-systemd Linux, restricted containers and macOS are currently unsupported. Optional basic process management and a platform containment interface are future work.
4. A native reaper observes exit independently of frontend/status polling, kills remaining descendants, cancels nonblocking input, drains bounded final output and joins PTY workers. PTY handles and input queues are released eagerly; exited status and bounded replay remain until tab closure. Close/launch/reaping operations run off the GTK thread. Attachment replacement still works after reader EOF.
5. Browser clipboard APIs failed under WebKitGTK. Selection changes and Ctrl+Shift+C use the native clipboard plugin. Asynchronous GTK clipboard conversion handles Ctrl+Shift+V text, copied-file URI lists and image-format detection without waiting on the WebView thread or holding a registry lock. Text/quoted paths use Ghostty's bracketed-paste API; images forward Ctrl+V to the running program. Ctrl+V also reaches Codex directly instead of being swallowed by the browser. Native tests cover drag selection/copy and image/file format detection; actual Codex image attachment remains manual. File drag-and-drop is not implemented.
6. Hidden painting suppression and independent screen updates pass the automated adapter check. Native hidden-tab floods and tab switching were measured; full session switching, selection retention and broader performance scenarios still need observation.
7. Closing the native window hides it without destroying the WebView or PTYs. A private activation socket reopens/focuses the existing instance on a second launch or --show. The SQLite writer lock serializes concurrent startup; only its owner may remove stale sockets. The footer Quit action confirms running processes, saves resume metadata and terminates sessions before exit. Processes do not survive Quit/crash/reboot; eligible commands start anew. Session/project/application CLI operations are implemented; terminal-specific CLI operations and distribution packages remain pending.

## SQLite design

Schema version 2 adds projects (stable ID, name, root, order, fold state) and session membership to sessions, typed tab definitions/configuration, open tabs, resume flags, selection and sequence counters. The migration rebuilds the referenced session table transactionally with foreign-key checking before commit, preserving existing tabs and selections. Existing sessions enter the Default group; existing paths stay unchanged. Built-in `terminal`, `files` and `pull-request` definitions have one opening per definition. Unknown plugin kinds/versions retain their configuration and show an unavailable panel; unknown database schema versions fail explicitly. PTY output and inherited environment are excluded. Versioned migrations and small metadata replacements are transactional. Failed writes restore editable in-memory metadata as well; process signals already delivered during a confirmed close cannot be undone if a later disk write fails, and that error is reported.

Successful launches set the resume flag. Explicit Stop/close and observed exit clear it. Shutdown records which processes are still running before terminating them. Loading metadata creates no PTYs; connected frontend controllers launch eligible commands once. Failed launches are reported without a restart loop. Crashes use the last committed running set, so these are fresh process instances with fresh terminal state, not recovered sessions.

An exclusive file lock prevents a second metadata writer and duplicate restoration launches. Metadata lock ownership is explicitly released on store drop, including while concurrent PTY fork/exec briefly retains a CLOEXEC duplicate. The owner starts a mode-0600 activation socket in the owner-only /run/user/<uid> directory. Same-UID peers may send version-2 JSON session/project/application commands, at most 128 KiB per request and 1 MiB per response. Each connection carries one request framed by write-side EOF and one JSON response followed by EOF. A single socket worker serializes requests; request reads have a two-second absolute deadline and writes a two-second timeout. CLI response reads have a 30-second absolute deadline. Neither side retries mutations automatically. Both sides check SO_PEERCRED. The CLI never opens SQLite or starts the app except through explicit app start. A small session-changed event invalidates frontend metadata after socket mutations, and the frontend refetches with sequence guards rather than applying possibly stale snapshots. New session actions start through that frontend; disconnected frontends leave metadata pending until reconnection. Terminal-specific RPC and snapshots are not implemented. Separate application data directories intentionally have separate instances. The application data directory is owner-only and the database is mode 0600. A missing session/root directory is retained without being recreated. Group root changes only set the initial directory for future session creation. Folding changes sidebar visibility only, and panes remain keyed by session/tab IDs. Each group reads its own app-config projects/<id>/actions.yaml; missing files use the bundled Bash/Codex/Files/Pull request defaults. The configuration uses actions and optional root env; there is no global-file or old-schema fallback. Form/YAML editing uses a shared validated Rust action model, bounded reads and atomic file replacement. Root env contains common project overrides, merged at each launch before action-specific overrides. The registry receives the app config directory during native setup; runtime environment merging never changes saved tab definitions or existing PTYs. Existing openings retain independent saved launch configuration.

No fallback terminal engine is selected. If ghostty-web fails the native gate, report the failing behavior and options before proceeding.

## Frontend reconnection

The connect operation reuses an existing live or exited session by stable tab ID before considering a new launch. Stopped tabs only launch when explicitly eligible under the existing startup policy. Attach replaces the channel, retires its pending acknowledgement and issues monotonically increasing sequence numbers, so a stale ACK cannot advance the replacement connection. Replay and live output share a single-envelope ACK window. A failed channel send pauses the reader until reattachment rather than discarding the PTY reader.

Replay rebuilds Ghostty from complete raw history and recorded resize events at its original dimensions. The frontend suppresses outbound input, terminal query responses and automatic resizing until a sequenced ready marker, then fits the visible container. The raw journal is transport recovery data, not a second terminal emulator or authoritative plain-text screen. Rendering, selection and scroll position are not checkpointed. Resize recording follows native processing order; timing relative to output already queued in the WebView is not a pixel-perfect frontend checkpoint. Native WebKitGTK reload/Codex behavior still requires interactive acceptance.

## Native validation and reused cells

Native WebKitGTK checks now exercise the actual Tauri app, IPC and Ghostty frontend on Wayland and X11/XWayland using private temporary metadata. Reload, interactive Codex editing/menu/resize, hidden output, query-response suppression, native clipboard shortcuts, flood bounds and terminal reuse observations are detailed in `VALIDATION.md`. The mouse adapter passes the current Wayland curses check; remaining manual and other-desktop checks still prevent declaring the complete gate passed.

An engine-level regression reproduced closed-terminal cells appearing in a new handle allocated from the same WASM instance. The app now sends RIS to each new emulator after its initial container fit and before output attachment, then redraws synchronously. This avoids showing stale pixels while waiting for the renderer's next animation frame. Resetting earlier, before the initial fit, was insufficient in native stress checks. It never resets an already running terminal during navigation or ordinary resizing. Thirty shared-engine cycles, ten native tab cycles and a single-line post-stress command verify clean screens while a live sibling retains its state.

## External action boundary

Project actions accept `kind: terminal` or `kind: command`. The latter prepares launch context from current registry metadata and common/action environment overrides, without creating a tab/session or changing SQLite. `actions/external.rs` expands a fixed set of session/project placeholders once, preserving literal argument boundaries; it never implicitly evaluates a command string. Shell-command mode receives reserved context environment variables instead of interpolated shell source. Creation skips command actions when choosing its initial terminal.

External launches use standard process spawning, null stdio and a new session, with at most 64 outstanding direct-child waiter threads. Each child is reaped and its exit reported to a connected frontend. They intentionally remain outside PTY cgroup ownership, terminal running counts, restart policy and session/Quit termination: desktop apps can outlive this app and may delegate to an existing desktop service. This is an explicit separate ownership contract, not daemon or background-task orchestration. Neither output nor external process metadata is persisted.

## DevCenter naming and paths

The npm/Cargo package is `devcenter`, the GUI executable is `devcenter-gui`, the CLI is `devcenter`, and the Codex wrapper is `dcodex`. Tauri's desktop identifier is `io.local.devcenter`; application configuration and metadata use explicit shared XDG paths named `devcenter` rather than deriving their names from the desktop identifier. GUI commands, CLI dispatch, startup, socket hashing, the wrapper and native validation fixtures share these paths. The original CLI/wrapper names remain aliases.

Before opening SQLite, GUI startup serializes legacy directory migration and checks the old metadata writer lock. It moves config and the complete data directory from `io.local.terminal-stack-prototype` to `devcenter`; independently created destinations cause an explicit conflict. Each rename is atomic; partial completion after an I/O failure can be retried. Client commands do not perform migration or access SQLite.

## Native terminal links

`src/terminal-links.ts` retains only bounded OSC 8 URL metadata while passing every original output byte to Ghostty. The existing engine supplies hyperlink cell IDs, cursor positions, wrapping and scrollback; its public `getHyperlinkUri` stub is adapted to look up retained URLs. URL metadata is limited to 8 KiB per OSC, 4,096 IDs and 4 Mi code units overall. Reconnection reconstructs it from the existing bounded replay journal; RIS clears stale metadata. The browser link detector then resolves labeled OSC 8 links and plain URLs against the same Ghostty buffer. Ctrl-click uses native GIO URI dispatch with HTTP(S)/local-file scheme restrictions, rather than WebKit `window.open`. Native validation uses a private registered URI handler so it never opens the user's browser.

## Persistent terminal text

The existing Ghostty buffer supplies up to 2,000 lines and approximately 60,000 UTF-16 code units for a text snapshot. Rust validates the runtime/tab association and 256 KiB wire/storage limit, then atomically replaces a private per-session/tab file on a blocking worker. Saves occur at most once per second on output, on EOF and before GUI Quit; abrupt termination and CLI Quit may omit the latest output. No second emulator or ANSI stripping is used to derive text.

A new runtime retains its original saved prefix independently of subsequent disk snapshots. Reattachment restores that same prefix before replaying the current runtime journal, avoiding duplicate current-process history. Disk text has terminal control characters removed before display; restored text cannot activate terminal modes or issue queries. Snapshots do not restore colors, modes or processes; terminal clear commands and alternate screens retain their usual behavior. A saved full-screen buffer is text from that active screen, not a transcript of everything the program displayed.

## Built-in plugin boundary

`src/plugins/index.tsx` registers identifiers, labels, supported configuration versions, content components, draft conversion/configuration editors and pre-Quit hooks. `TabHost` keeps content keyed by stable tab IDs. Component attachment effects own resources, visibility props drive paint/polling behavior, and effect cleanup disposes resources on closure. The terminal plugin retains its controller across navigation; `src/terminal.ts` is a compatibility export. The terminal launch form is plugin-owned and reused by independent external commands.

Rust plugin modules own configuration validation and specialized operations. Shared registry methods own generic create/configure/open/select/reorder/close operations for both UI and CLI; terminal raw-byte transport stays specialized. Schema 4 stores `{version, config}` inside the existing `config_json` column and the plugin identifier in `kind`. The migration wraps existing payloads atomically without rewriting IDs, openings or restart eligibility. Schema 5 adds `sessions.pull_request_json` for an optional explicit GitHub association. It handles both schema-4 variants, with or without the association column, without wrapping plugin payloads again. Missing plugins are kept opaque during loading and can still be selected, reordered or closed; opening/configuring requires an available validator. Existing unavailable project actions remain opaque when reading launch settings and are filtered from New tab. Saving edited YAML requires available validators for every action, so unsupported entries must be resolved explicitly.

Schema 6 adds a separate, versioned archive payload table and monotonic archive ID sequence. Session removal and tab-definition deletion move their plugin-independent metadata to this table in the same transaction as active metadata changes. Plain CLI tab closure still retains its active definition; the GUI tab cross archives it. The Rust registry owns 30-day retention, restoration and two-phase artifact purge. Age is measured from archival time; startup and each new archive trigger cleanup. Restoration retains stable IDs and opening state, with terminal restart flags captured from observed running processes. Fresh terminal launches remain frontend-driven; no process or unsaved buffer is preserved in an archive. Independently archived tabs require their archived parent session to be restored first. Archived project metadata can recreate a removed project without touching its root. A committed purge marker prevents restoration after cleanup starts and permits retry after failure; only matching DevCenter history/Codex mapping artifacts are removed. UI and CLI use these shared operations, and maintenance errors remain visible in Archives without blocking startup.

The file plugin scans bounded `read_dir` results on blocking workers, filters hidden names/search, sorts folders first and delivers bounded batches for infinite scrolling. It follows directory symlinks through canonicalization and transactionally remembers the current folder and optional open editor file in each tab’s SQLite JSON configuration. Folder updates preserve the editor file; returning to Files clears only the editor file. Startup/reload reopens saved disk contents, retaining missing paths with a recoverable error. Concurrent directory changes can shift batch boundaries. It creates neither Ghostty emulators nor PTYs. UTF-8 text files up to 1 MiB open in a plain-text CodeMirror editor; binary files delegate to their associated applications through native GIO. Native saves compare loaded revisions and atomically replace writable, user-owned single-link files, preserving ordinary access permissions, group, uniform LF/CRLF and BOM. ACLs/extended attributes are not retained; checks immediately before replacement do not provide atomic conflict detection against unrelated writers. GUI back/reload/close/Quit protect unsaved changes, but CLI destruction, crashes and WebView reload can discard in-memory edits. See README for editor limits.

The PR plugin invokes authenticated `gh pr view` with argument arrays, null stdin and nonblocking bounded stdout/stderr. Requests time out after 20 seconds, allow at most 32 active tab jobs, and reject overlapping requests for the same tab. Cancellation tokens are set on tab/session closure, association changes and Quit; workers poll cancellation and terminate/reap the subprocess group. Closure/Quit waits for their completion acknowledgement before removing a job or exiting; a cleanup timeout reports an error and leaves the application alive. React retains the last successful result/time across refresh failures and polls every 60 seconds only while its tab/session is visible. Results are not persisted. The association is session-owned; configuration remains plugin-owned. No Git discovery, PR mutations or authentication-token storage is added.
