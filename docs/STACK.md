# Stage-one stack evaluation

Current scope: collapsible workgroups containing workspaces, terminal tabs, and SQLite metadata. At the user's request, previously running commands launch anew on application startup. Definitions and current openings are distinct; closing a tab retains its metadata internally. New tab creates a fresh opening from a user YAML type; the saved-definition reopening selector is no longer exposed. Each terminal has an independent PTY and emulator. This does not mark all interactive validation checks complete or certify every supported Linux environment.

## Candidate and licensing

The inspected and installed candidate is [`coder/ghostty-web`](https://github.com/coder/ghostty-web), npm version **0.4.0**, pinned in package.json and package-lock.json. Its package metadata and [upstream license](https://github.com/coder/ghostty-web/blob/main/LICENSE) declare MIT. Published runtime dependencies are empty. Upstream's development tools include xterm packages for comparisons; this application neither installs nor uses those packages.

This is a third-party integration around a patched Ghostty WASM build, not a supported native Ghostty surface or a promise of official browser support. Before distribution, include the applicable Ghostty and ghostty-web license notices and record the source revision/build provenance for the shipped WASM.

The Ghostty VT engine handles byte parsing and screen state. **WASM alone is not a browser terminal.** ghostty-web provides Canvas rendering, font measurement, input encoding, selection, clipboard integration, mouse handling, and scrolling in TypeScript. Every one of these browser-facing behaviors must be tested under WebKitGTK rather than inferred from native Ghostty or Chromium.

## API actually used

The installed declarations and distributed JavaScript were inspected, alongside [upstream sources](https://github.com/coder/ghostty-web/tree/main/lib). The prototype uses `Ghostty.load(assetUrl)` and a `Terminal({ ghostty })` rather than relying on `init()` to guess an asset path. Vite imports the package's exported WASM with `?url`, placing a fingerprinted local asset into the build. No CDN is used at runtime.

Other used APIs: `open`, `write(Uint8Array)`, `onData`, `onResize`, `FitAddon`, `paste`, `getSelection`, `buffer.active.getLine().translateToString()`, `dispose`, and `attachCustomKeyEventHandler`. In this version the custom handler returns true when it handles an event. Its semantics differ from some other terminal APIs despite the compatibility-oriented names.

In 0.4.0, `write` parses into WASM synchronously; its optional completion callback is scheduled through requestAnimationFrame. The output ACK is sent after the synchronous parse, without waiting for a paint, because hidden-window animation frames may pause. Reevaluate this assumption when upgrading the library.

## Ownership and limits

- `TerminalSession` owns the PTY and child independently of React. Commands address a session ID. This provides a boundary that can later move behind a daemon; no daemon exists here.
- Rust reads raw bytes in chunks up to 16 KiB. Exactly one data envelope can remain unacknowledged in the Tauri channel. Reading stops until the frontend ACKs, so pressure propagates back to the PTY producer. A raw byte/resize replay journal is bounded by a 4 MiB per-session accounting budget; replay holds at most one additional bounded copy plus a live chunk. On overflow the journal is discarded and reconnection explicitly warns that the previous screen cannot be restored. On natural exit, the reaper allows up to an additional 1 MiB of bounded PTY tail draining without frontend ACKs so native handles/workers can be released even if the frontend is detached; the IPC envelope window remains one. Excess tail is explicitly discarded with an error. No output is persisted to disk.
- JavaScript converts byte arrays directly to Uint8Array. It does not decode each chunk independently. Ghostty retains partial UTF-8 and VT parser state.
- Scrollback is configured to 2,000 lines. Input has a 64 KiB frontend budget, 8 KiB native writes, and a bounded one-request native input queue. A dedicated writer avoids holding the session lock while waiting for PTY input space.
- React keeps one persistent controller per tab, keyed by its stable ID inside its workspace. Container resizing uses ResizeObserver and ignores zero-sized containers. Closing explicitly disposes emulator resources and subscriptions. Tab/workspace selection and reordering change visibility/order rather than mounting new terminals.
- Workspaces retain their own selected tab. Session IDs identify a launch; stable tab IDs identify configuration across explicit stop/restart. Sessions are indexed by tab ID, not workspace ID. Workspace closure checks confirmation before terminating any of its tab sessions. The UI uses the same registry methods intended for future CLI control.
- Tab configuration contains an optional directory override, optional executable, argument array, explicit environment overrides, and optional explicit shell-command mode. Rust resolves the current workspace directory at launch when no override exists. Shell-command mode invokes the user's shell with `-lc`; direct mode passes literal arguments without shell evaluation. The inherited environment is not stored in metadata.
- All controllers share the loaded Ghostty WASM instance but use separate terminal handles. Hidden workspaces still parse and ACK raw bytes; their public `CanvasRenderer.render` method is gated off. Document-hidden windows also suppress painting; restoring visibility fits the container and forces a redraw. Upstream's lightweight per-terminal animation/cursor polling remains; private animation-loop fields are not patched. Recheck this adapter when upgrading ghostty-web.
- The authoritative terminal screen is in the frontend's existing Ghostty instance. The snapshot adapter reads that buffer, limited to the visible screen and 65,536 JavaScript code units. There is no second emulator and no regex ANSI stripping. The future CLI must report snapshot-unavailable when this frontend is disconnected. A hidden but connected frontend supplies snapshots from the same emulator; native lifecycle checks verify continued output while hidden.

## Open blockers and limits

1. **Observed browser-input blocker:** the native Wayland curses probe receives no mouse reports. ghostty-web 0.4.0 tracks mouse modes in WASM, but its browser canvas handlers select text rather than forwarding mouse reports to the PTY. Passing engine mode checks does not implement mouse reporting. Add/validate a browser input adapter or an upstream fix before claiming mouse-app compatibility. No alternate terminal engine has been selected.

2. Remaining interactive Codex and browser-facing checks are tracked in the native validation checklist. User feedback authorized the sidebar work; builds and engine checks alone still do not certify those behaviors.
3. Terminal launch requires writable systemd user cgroup v2 delegation, cgroup.kill, and pidfds. The bootstrap re-execs the live application through `/proc/<app-pid>/exe`, preserving the same image/protocol even if a rebuild or update deletes/replaces its original pathname. `current_exe()` can return a nonexistent path ending in `(deleted)` and must not be used as the production launch path. The bootstrap joins a new per-terminal cgroup before exec; failure rejects launch, without a process-group or /proc fallback. Confirmed close/Quit atomically SIGKILL the cgroup and wait for it to empty. This includes inherited descendants that setsid or double-fork. A short-lived watchdog outside the leaf monitors application and command-leader pidfds, kills the leaf on either death, removes it, and exits. Leader exit intentionally ends its remaining background jobs. No graceful interval or persistent daemon is implemented. This is not a security sandbox: deliberate same-user cgroup migration and work delegated to external services are outside ownership. The implementation is Linux/systemd-specific; non-systemd Linux, restricted containers and macOS are currently unsupported. Optional basic process management and a platform containment interface are future work.
4. A native reaper observes exit independently of frontend/status polling, kills remaining descendants, cancels nonblocking input, drains bounded final output and joins PTY workers. PTY handles and input queues are released eagerly; exited status and bounded replay remain until tab closure. Close/launch/reaping operations run off the GTK thread. Attachment replacement still works after reader EOF.
5. Browser clipboard reads failed with NotAllowedError during user testing. Ctrl+Shift+C/V use Tauri's native clipboard-manager plugin with text-only read/write permissions. Paste still goes through Ghostty's paste API to preserve bracketed paste. The user confirmed the fix works; the broader selection/clipboard checklist remains open.
6. Hidden painting suppression and independent screen updates pass the automated adapter check. Native hidden-tab floods and tab switching were measured; full workspace switching, selection retention and broader performance scenarios still need observation.
7. Closing the native window hides it without destroying the WebView or PTYs. A private activation socket reopens/focuses the existing instance on a second launch or --show. The SQLite writer lock serializes concurrent startup; only its owner may remove stale sockets. The footer Quit action confirms running processes, saves resume metadata and terminates sessions before exit. Processes do not survive Quit/crash/reboot; eligible commands start anew. Full CLI operations and distribution packages remain pending.

## SQLite design

Schema version 2 adds workgroups (stable ID, name, root, order, fold state) and workspace membership to workspaces, typed tab definitions/configuration, open tabs, resume flags, selection and sequence counters. The migration rebuilds the referenced workspace table transactionally with foreign-key checking before commit, preserving existing tabs and selections. Existing workspaces enter the Default group; existing paths stay unchanged. Only `terminal` definitions are supported today, with one opening per definition. Unknown kinds/schema versions fail explicitly. PTY output and inherited environment are excluded. Versioned migrations and small metadata replacements are transactional. Failed writes restore editable in-memory metadata as well; process signals already delivered during a confirmed close cannot be undone if a later disk write fails, and that error is reported.

Successful launches set the resume flag. Explicit Stop/close and observed exit clear it. Shutdown records which processes are still running before terminating them. Loading metadata creates no PTYs; connected frontend controllers launch eligible commands once. Failed launches are reported without a restart loop. Crashes use the last committed running set, so these are fresh process instances with fresh terminal state, not recovered sessions.

An exclusive file lock prevents a second metadata writer and duplicate restoration launches. Metadata lock ownership is explicitly released on store drop, including while concurrent PTY fork/exec briefly retains a CLOEXEC duplicate. The owner starts a mode-0600 activation socket in the owner-only /run/user/<uid> directory. Same-UID peers may send a versioned show request of at most 1,024 bytes; read/write deadlines bound stalled clients. Separate application data directories intentionally have separate instances. The application data directory is owner-only and the database is mode 0600. A missing workspace/root directory is retained without being recreated. Group root changes only set the initial directory for future workspace creation. Folding changes sidebar visibility only, and panes remain keyed by workspace/tab IDs. Each group reads its own app-config workgroups/<id>/actions.yaml; legacy global YAML is copied only when initializing a missing file. Existing openings retain independent saved launch configuration.

No fallback terminal engine is selected. If ghostty-web fails the native gate, report the failing behavior and options before proceeding.

## Frontend reconnection

The connect operation reuses an existing live or exited session by stable tab ID before considering a new launch. Stopped tabs only launch when explicitly eligible under the existing startup policy. Attach replaces the channel, retires its pending acknowledgement and issues monotonically increasing sequence numbers, so a stale ACK cannot advance the replacement connection. Replay and live output share a single-envelope ACK window. A failed channel send pauses the reader until reattachment rather than discarding the PTY reader.

Replay rebuilds Ghostty from complete raw history and recorded resize events at its original dimensions. The frontend suppresses outbound input, terminal query responses and automatic resizing until a sequenced ready marker, then fits the visible container. The raw journal is transport recovery data, not a second terminal emulator or authoritative plain-text screen. Rendering, selection and scroll position are not checkpointed. Resize recording follows native processing order; timing relative to output already queued in the WebView is not a pixel-perfect frontend checkpoint. Native WebKitGTK reload/Codex behavior still requires interactive acceptance.

## Native validation and reused cells

Native WebKitGTK checks now exercise the actual Tauri app, IPC and Ghostty frontend on Wayland and X11/XWayland using private temporary metadata. Reload, interactive Codex editing/menu/resize, hidden output, query-response suppression, native clipboard shortcuts, flood bounds and terminal reuse observations are detailed in `VALIDATION.md`. The complete gate remains blocked by mouse reporting and remaining manual checks.

An engine-level regression reproduced closed-terminal cells appearing in a new handle allocated from the same WASM instance. The app now sends RIS to each new emulator after its initial container fit and before output attachment, then redraws synchronously. This avoids showing stale pixels while waiting for the renderer's next animation frame. Resetting earlier, before the initial fit, was insufficient in native stress checks. It never resets an already running terminal during navigation or ordinary resizing. Thirty shared-engine cycles, ten native tab cycles and a single-line post-stress command verify clean screens while a live sibling retains its state.
